## Client differences in the upstream implementation

- Bun receives `signal` in `reserve`, while postgres.js does not; after a session is killed, the Bun pool is closed with `timeout: 0`. [Code](https://github.com/kysely-org/kysely-postgres-js/blob/2ddcc39a07872f01e6dda3b722d8dcc9d5759858/src/driver.ts#L35-L81).
- postgres.js cancellation uses `pendingQuery.cancel()`; for Bun, the driver obtains the PID in a separate query and uses `pg_cancel_backend`. With `kill session`, postgres.js first cancels the query and waits for error `57014`, while Bun uses `pg_terminate_backend`. This describes the upstream implementation and comments, not an independent verification of library behavior. [Cancellation and PID](https://github.com/kysely-org/kysely-postgres-js/blob/2ddcc39a07872f01e6dda3b722d8dcc9d5759858/src/driver.ts#L179-L205), [kill](https://github.com/kysely-org/kysely-postgres-js/blob/2ddcc39a07872f01e6dda3b722d8dcc9d5759858/src/driver.ts#L246-L297), [control query](https://github.com/kysely-org/kysely-postgres-js/blob/2ddcc39a07872f01e6dda3b722d8dcc9d5759858/src/driver.ts#L331-L377).
- The driver explicitly rejects Bun.SQL streaming; postgres.js uses a cursor and checks that `chunkSize` is a positive integer. [Code](https://github.com/kysely-org/kysely-postgres-js/blob/2ddcc39a07872f01e6dda3b722d8dcc9d5759858/src/driver.ts#L299-L328). For Bun >= 1.3.13, a test helper substitutes `AbortController` for `AbortSignal.timeout` because of a regression described upstream. [Helper](https://github.com/kysely-org/kysely-postgres-js/blob/2ddcc39a07872f01e6dda3b722d8dcc9d5759858/tests/test-setup.ts#L79-L103).

- Biome, Deno lint and a build with `attw`/`publint`, CodeQL, dependency review, `pnpm audit`, and zizmor are defined separately. Vitest typechecking is enabled with `ignoreSourceErrors: true`; a separate `check:types` exists but is not explicitly invoked in the listed test/check workflows. [Checks](https://github.com/kysely-org/kysely-postgres-js/blob/2ddcc39a07872f01e6dda3b722d8dcc9d5759858/.github/workflows/check.yml#L39-L54), [build](https://github.com/kysely-org/kysely-postgres-js/blob/2ddcc39a07872f01e6dda3b722d8dcc9d5759858/tsdown.config.ts#L3-L8), [typecheck](https://github.com/kysely-org/kysely-postgres-js/blob/2ddcc39a07872f01e6dda3b722d8dcc9d5759858/vitest.config.ts#L4-L10), [CodeQL](https://github.com/kysely-org/kysely-postgres-js/blob/2ddcc39a07872f01e6dda3b722d8dcc9d5759858/.github/workflows/codeql.yml#L12-L47), [dependency review](https://github.com/kysely-org/kysely-postgres-js/blob/2ddcc39a07872f01e6dda3b722d8dcc9d5759858/.github/workflows/dependency-review.yml#L3-L31), [security](https://github.com/kysely-org/kysely-postgres-js/blob/2ddcc39a07872f01e6dda3b722d8dcc9d5759858/.github/workflows/secure.yml#L10-L55).
- Explicit limitations of this snapshot: there is no prepared-statement reuse test for Bun.SQL; ordinary stream tests are skipped for it, and there is no separate check of the unsupported-stream error text. The specified test workflow has no PostgreSQL version or OS matrix; the four test files also have no separate scenarios for arrays, JSON, `numeric`/`bigint`, or binary data. These are absences of visible tests in this snapshot, not claims that the features are broken.
